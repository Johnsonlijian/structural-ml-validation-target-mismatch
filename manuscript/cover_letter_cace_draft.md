Dear Editor,

We submit this manuscript to *Computer-Aided Civil and Infrastructure Engineering* because it delivers a **reproducible computational validation pipeline** for structural and infrastructure machine learning: a deployment-target taxonomy, grouped and deployment-matched cross-validation machinery, group-topology diagnostics, and a reporting checklist that align headline scores with the engineering use case. The work is intentionally **not** a field-wide prevalence survey; it provides an executable protocol, nine public benchmark modules (Structural ML-Bench v1.0), and a 332-paper OpenAlex sampling frame for future scaling.

Three contributions match the journal scope:

1. **Computational protocol** — Source-Aware Validation Protocol (SAVP) replaces naive random splitting with target-matched evaluation, pooled regression summaries, and classification metrics (macro-F1, balanced accuracy) where class/group topology stresses naive accuracy.
2. **Heterogeneous empirical evidence** — The nine modules form a **stress-test portfolio** with built-in **adversarial controls** (negligible optimism and a grouped-validation contrast case), so the protocol is not tuned only to large gaps.
3. **Open engineering artefacts** — Deterministic Python workflows regenerate `Table S7`, **Figure S5** and the graphical abstract; a versioned GitHub repository and Zenodo DOI are quoted in **Code availability** (placeholders replaced at upload). If the public DOI is not yet live, an equivalent zip bundle is available to editors and reviewers on request.

We specifically cite Reich (1997), Adeli (2001), Sgambi et al. (2012), Valikhani et al. (2021) and Fayaz & Galasso (2023) to anchor the work in *Computer-Aided Civil and Infrastructure Engineering*’s computational-learning tradition while supplying the missing deployment-aligned validation layer for contemporary ML surrogates.

We believe the checklist and machine-readable tables can support reviewers and practitioners who must decide whether a model is being claimed for interpolation within a database, out-of-source transport, mixture drift or structural-family extrapolation. Thank you for considering the manuscript for editorial assessment.
